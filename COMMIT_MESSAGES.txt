# Commit 1: mTLS Infrastructure Package

Subject: feat(mtls): Add mTLS certificate management package

Description:
Implement payment-util/mtls package for production-grade mutual TLS support.

Changes:
- mtls/mtls.go: Config loader, TLS builders, credential factories
- mtls/helpers.go: X.509 certificate parsing utilities
- mtls/doc.go: Package documentation with usage examples
- serviceregistry/dial.go: Add MTLSDialOptions() helper

Features:
- LoadFromEnv() loads certificate paths from MTLS_SERVER_CERT/KEY/CA_CERT
- ServerTLSConfig() and ClientTLSConfig() for tls.Config building
- ServerCredentials() and ClientCredentials() return gRPC credentials
- Certificate expiration validation with fail-fast on expired certs
- Production enforcement: missing certs cause startup panic
- Development compatibility: INSECURE_DIAL=1 allows fallback in non-prod

Environment Variables:
- MTLS_SERVER_CERT: Path to server certificate (PEM format)
- MTLS_SERVER_KEY: Path to server key (PEM format)
- MTLS_CA_CERT: Path to CA certificate (PEM format)
- ENVIRONMENT: Set to "prod"/"production" for strict enforcement
- INSECURE_DIAL: Set to "1" to allow insecure mode (dev only)

This addresses the critical audit finding: api-gateway ↔ user-merchant-core
must use mTLS instead of insecure.NewCredentials().
